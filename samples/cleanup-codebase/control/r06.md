To get started, point me at the project and the failure. The most useful things are:

- The path to the repository, if it's somewhere else on this machine.
- The actual error output from the failing deploy, ideally the last 50 lines or so of the log rather than just the final line.
- Where it's deploying to and what runs the deploy (GitHub Actions, a Dockerfile, a hosting provider's build step, a shell script).
- Whether the same commit deployed successfully before yesterday, or whether the code changed too.

That last point tends to be the fastest split. If an unchanged commit now fails, the cause is outside your repo, usually a floating dependency version, a base image tag that moved, an expired token or certificate, or a provider changing a default. If the code changed, we can bisect against the last good deploy instead.
