Most useful, in rough order:
- The failing build/deploy log, especially the first error rather than the last one. Later errors are usually fallout.
- Path to the repo on this machine, if it's local.
- What deploys it: GitHub Actions, GitLab CI, Vercel, Fly, Kubernetes, a shell script.
- Whether anything shipped in the last two days: a merge, a dependency bump, a base image tag that moves (`node:22`, `ubuntu:latest`), a rotated credential, an expired cert.

If it worked Friday and broke Saturday with no commits in between, the cause is almost always outside your repo: a floating tag pulled a new image, a token expired, a registry or package mirror changed, or a CI runner image rolled. That class of failure shows up in the log's setup phase, not in your build steps.
