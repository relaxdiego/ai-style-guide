SQLite, unless you can name a specific Postgres feature you need on the client.

Local-first means the database ships to end-user machines, and that packaging cost is what decides it. Postgres wants a server process, a data directory, `initdb` on first run, a port or socket, and a per-platform binary you bundle and keep patched. SQLite is a library you link. Your database is one file the user can copy, and crash recovery is handled for you. The local-first sync ecosystem has already made this choice for you too: PowerSync, ElectricSQL, Turso/libSQL and cr-sqlite all put SQLite on the client and Postgres on the server, so the common architecture uses both rather than picking one.

Reach for Postgres on the client only if you hit one of these:

| Need | Why SQLite fails |
|---|---|
| Several OS processes writing concurrently | One writer at a time, even in WAL mode |
| PostGIS, or ranked full-text beyond FTS5 | No equivalent extension |
| Stored procedures, materialised views, real check-constraint DDL | Absent or heavily limited |
| "Local" actually means a dev mirror of prod Postgres | Dialect drift will bite you in tests |

The SQLite constraints you should design around from day one:

- Enable WAL and set `busy_timeout`; keep write transactions short. A long write blocks every other writer.
- Use `STRICT` tables (3.37+) or you get dynamic typing and silent coercion.
- No date/time type. Store integer epoch or ISO-8601 text and be consistent.
- `ALTER TABLE` is limited; schema migrations often mean create-copy-drop-rename.
- Never put the file on NFS/SMB. Locking is unreliable there.

On the fear of getting it wrong: the engine is the cheap half of this decision and the reversible one. Portable SQL, an integer timestamp convention, and a query layer that isn't leaning on dialect-specific upsert syntax will move between the two in days. What you can't cheaply reverse is the sync and conflict-resolution model — last-write-wins versus CRDTs versus server-authoritative — and picking SQLite doesn't commit you on any of that. Spend your caution there.
