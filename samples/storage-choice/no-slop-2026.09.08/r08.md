SQLite, unless "local-first" is doing something unusual in your sentence.

Postgres on an end-user device means shipping a server process, a port, a data directory, and a major-version upgrade path (`pg_upgrade` or dump/restore) that you now own on machines you can't log into. SQLite is a library that compiles into your binary and writes one file. For an app that runs on the user's machine, that difference dominates everything else on the list.

Where Postgres actually wins:

- Multiple machines or users write the same database concurrently. SQLite has one writer at a time; WAL mode gives you concurrent readers, not concurrent writers.
- You need extensions: PostGIS, pgvector, real full-text search at scale.
- Analytical queries over millions of rows with query-plan tuning, partial indexes on expressions, parallel scans.
- "Local-first" means self-hosted on a box someone administers, not an app on a laptop or phone. That's a different thing wearing the same phrase.

The decision that's expensive to reverse is not the engine, it's sync. If two devices can edit the same data offline, you need a conflict model, and that choice reaches into your schema (row versions, tombstones, per-field timestamps, or CRDT structures). Pick that before you pick the database:

| Sync need | Reasonable pick |
|---|---|
| Single device, no sync | Plain SQLite, WAL mode, STRICT tables |
| Single device, backup/restore | SQLite plus Litestream or file sync of one file |
| Multi-device, server of record | SQLite on client, Postgres on server, ElectricSQL or PowerSync between them |
| Multi-device, real offline collaboration | CRDT layer (Automerge, Yjs, cr-sqlite) with SQLite as the store |

Swapping SQLite for Postgres later costs you a migration script and whatever dialect-specific SQL you wrote; keep queries behind one data-access module and that stays a few days of work. Two SQLite specifics to set on day one because they're annoying later: turn on WAL mode, and declare tables `STRICT` so column types are enforced instead of coerced.

So: how many devices per user, and do two of them ever edit the same record while offline? That answers it. If the answer is one device, stop reading and use SQLite.
