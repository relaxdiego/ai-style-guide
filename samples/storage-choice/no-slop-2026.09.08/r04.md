SQLite, unless you have a server tier that also needs to own data. "Local-first" means the app reads and writes a local copy and keeps working offline; Postgres does not embed, so choosing it means every read crosses a socket to a daemon you now have to install, supervise, and version-match on user machines.

The real question is not the engine, it's sync. Storage engine is a few weeks of work to swap; a sync design (conflict resolution, tombstones, causality, schema migration across clients on different versions) is the part that gets locked in and is expensive to change later.

| Concern | SQLite | Postgres |
|---|---|---|
| Ships inside your process | yes | no, separate daemon |
| Per-user file you can copy, back up, or hand to sync | yes | no, cluster-wide data dir |
| Concurrent writers | one at a time (WAL gives concurrent readers) | many |
| Types, JSONB, partial indexes, window functions | decent, JSON1 covers most | stronger |
| Full-text search | FTS5, good enough for local corpora | tsvector, better |
| Extensions for sync/CRDT | cr-sqlite, Electric, litestream, Turso | logical replication, ElectricSQL server side |

Where Postgres actually wins in a local-first setup: it's the server-side half. Common shape is SQLite on each client, Postgres as the central store, replication between them. That's ElectricSQL, PowerSync, and Turso's model, and it's the one I'd default to if you need multi-user or server-side queries.

Pick Postgres on the client only if you hit one of these: write concurrency from multiple OS processes hammering the same database, a dependency on a Postgres-only extension (PostGIS, pgvector at scale), or your "local" is actually a single-tenant server box rather than an end-user laptop.

Two things to decide now, since they're harder to reverse than the engine:
- Whether row IDs are UUIDs/ULIDs generated client-side. Autoincrement integers will fight sync forever.
- Whether you write an append-only log of changes alongside the current state. Retrofitting one onto existing tables is painful.

What's the deployment shape? If there's no server at all and no multi-device sync, SQLite and you're done thinking about this.
