Git stored the script without the executable bit, so the runner checks out mode 644. Locally your file is executable because you `chmod +x`'d it after creating it, and that change never made it into the index.

Confirm it:

```
git ls-files -s path/to/script.sh
```

`100644` is the broken case, `100755` is what you want.

Fix it in the index and push:

```
git update-index --chmod=+x path/to/script.sh
git commit -m "mark script.sh executable"
```

Common ways this happens:

| Cause | Tell |
|---|---|
| `chmod +x` after `git add`, never re-added | Local file is executable, `ls-files -s` says 100644 |
| `core.fileMode=false` in your config | Git ignores your local mode entirely |
| File added through the GitHub web UI or a Windows checkout | Never had a mode bit to record |

Two workarounds if you want the job green before that lands: invoke it as `bash path/to/script.sh` in the workflow step, which ignores the mode bit, or add `chmod +x path/to/script.sh` as a step before the call. Both hide the real problem, so still fix the index.
