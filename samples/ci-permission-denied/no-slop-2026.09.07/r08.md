Git did not record the executable bit on the script. Your local copy has mode 755 from when you created it, but the blob committed is 100644, so the fresh checkout on the runner gets a non-executable file and `./script.sh` fails with permission denied.

Check what git actually stored:

```bash
git ls-files -s path/to/script.sh
```

`100644` confirms it. Fix and commit:

```bash
git update-index --chmod=+x path/to/script.sh
git commit -m "Make script.sh executable"
```

Common causes:

| Cause | Tell |
|---|---|
| `core.fileMode=false` in your local config | git ignores mode changes entirely; `git config core.fileMode` returns false |
| File created on Windows or a filesystem without the bit | mode is 644 for every file you add |
| File added by an editor or generator, then chmod'd after `git add` | mode change never staged |

Two other things produce the same error message on Actions, so rule them out if the mode is already `100755`:

- Missing or CRLF shebang. `#!/bin/bash\r` makes the kernel look for an interpreter literally named `bash\r`, and the error surfaces as permission denied or "bad interpreter". Run `file script.sh` or `head -c 20 script.sh | xxd`.
- The script lives on a volume mounted `noexec`, which happens inside some container jobs.

The workaround of `run: bash script.sh` instead of `run: ./script.sh` also works and sidesteps the mode entirely, but fix the bit anyway so the script stays runnable for anyone who clones the repo.
