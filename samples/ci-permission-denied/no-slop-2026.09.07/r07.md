The script is committed with mode 100644. Git stores only the executable bit, and your local copy has +x from the filesystem while the index does not, so the runner checks out a non-executable file.

Confirm it:

```
git ls-files -s path/to/script.sh
```

`100755` is executable, `100644` is not. If it says 100644, fix it without touching the file contents:

```
git update-index --chmod=+x path/to/script.sh
git commit -m "Make script.sh executable"
```

Common reasons the bit got lost:

| Cause | Tell |
|---|---|
| `core.fileMode=false` in your config | Local chmod never registers as a change |
| Checkout on Windows or a mounted filesystem | Everything shows 100644 |
| File created by a script or editor without +x, then chmod'd after `git add` | Working tree and index disagree |
| Repo cloned onto exFAT/NTFS | No permission bits at all |

Two workarounds if you would rather not depend on the mode: call it as `bash path/to/script.sh` in the workflow step, or add `chmod +x path/to/script.sh` before the invocation. Both work, but fixing the index entry is the one that keeps local and CI behaviour identical.
