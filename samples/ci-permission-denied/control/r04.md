Almost certainly git recorded the script as mode 100644, so the runner checks it out non-executable.

Locally the file has the exec bit because your editor or `chmod` gave it one on your filesystem, and running `./script.sh` uses that. Git stores only one bit of permission per file, and it captures it at the moment you `git add` the file. If the file was not executable at that instant, or if your repo has `core.fileMode=false` (common on Windows, WSL and some network mounts), git wrote `100644` into the index and no later `chmod` will change it without telling git explicitly. The checkout on Actions is a fresh clone, so it reproduces exactly what is in the tree: a 644 file, and `./script.sh` gives "permission denied".

Check and fix it with:

```bash
git ls-files -s path/to/script.sh     # want 100755, not 100644
git update-index --chmod=+x path/to/script.sh
git commit -m "Make script.sh executable"
```

`git update-index --chmod` works regardless of `core.fileMode` and regardless of the file's permissions on disk, which is why it is the right tool here rather than `chmod +x` followed by `git add`.

If `git ls-files -s` already shows `100755`, the cause is somewhere between the checkout and the invocation, and the usual candidates are:

- The script reaches the job through `actions/upload-artifact`/`download-artifact` or `actions/cache` rather than through the checkout. Neither preserves the executable bit, so you need a `chmod +x` step after the download.
- The script is generated or fetched by an earlier workflow step, in which case it is created 644 by default and needs the same treatment.
- The job runs in a container where the working directory is mounted `noexec`, or as a user without execute permission on a parent directory.

As a workaround at the call site, invoking it as `bash path/to/script.sh` bypasses the exec bit entirely, since the kernel never has to exec the file. That is worth doing if the script is only ever called from your workflow, but it hides the problem from anyone running it by hand, so fixing the mode in the tree is the better resolution.
