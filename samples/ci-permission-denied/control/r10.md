Your script is almost certainly committed with mode `100644`, so the checkout on the runner produces a file without the executable bit.

Git tracks exactly one permission bit per file, executable or not, and nothing else about the mode. Locally the script runs because the copy sitting in your working tree got the bit when you created it, or because you invoke it as `bash scripts/foo.sh` while the workflow invokes it as `./scripts/foo.sh` or as a `run:` step that execs it directly. Neither of those depends on what git recorded, so the missing bit stays invisible until a fresh clone happens somewhere else.

Check what was actually committed, and fix it in the index rather than on disk:

```
git ls-files -s scripts/foo.sh
# 100644 ... -> not executable
# 100755 ... -> executable

git update-index --chmod=+x scripts/foo.sh
git commit -m "Make scripts/foo.sh executable"
```

`git update-index --chmod=+x` is the reliable form because it writes the mode into the index directly. Plain `chmod +x` followed by `git add` works too, but only when the filesystem carries the bit and git is watching it, which is why the usual trap here is `core.fileMode`. If it is set to `false`, either explicitly or automatically on Windows and on some network or container-mounted filesystems, git ignores mode changes entirely and your `chmod +x` produces no diff to commit. Run `git config core.fileMode` to see whether that is what has been swallowing the fix.

If `git ls-files -s` already shows `100755`, then the runner is not getting the file from the checkout. The common culprit is `actions/upload-artifact`, which packs into a zip and drops permission bits, so a script that travels between jobs as an artifact arrives non-executable however it was committed; the fix there is a `chmod +x` step after the download. One symptom worth ruling out separately: a script with CRLF line endings fails with `bad interpreter: /bin/bash^M` rather than `permission denied`, so if that is the message you are seeing, the cause is `.gitattributes` and line endings instead of the mode.
