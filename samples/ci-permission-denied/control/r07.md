Almost certainly the executable bit was never committed. Git records file mode, and your local copy has a permission the repository doesn't.

Check it with `git ls-files -s path/to/script.sh`: a leading `100644` means git has it as non-executable, `100755` means executable. Locally the script works because the file on your disk kept whatever mode it had when you created it, or because you invoke it as `bash script.sh` while the workflow calls `./script.sh` directly. The checkout on the runner is built from what git stored, so it lands as mode 644 and `./script.sh` fails with permission denied.

The fix commits the bit rather than setting it on disk:

```
git update-index --chmod=+x path/to/script.sh
git commit -m "Make script.sh executable"
```

`git update-index --chmod` writes the mode into the index directly, which matters because a plain `chmod +x` records nothing when `core.fileMode` is false — the default on Windows and on some Linux setups with a repo on a filesystem that doesn't carry the bit. If you're on macOS or Linux with `core.fileMode` true, `chmod +x` followed by a commit does the same job, and `git diff` will show you `old mode 100644 / new mode 100755` as confirmation.

If `git ls-files -s` already shows `100755`, the next suspects are:

- **The script passes through `upload-artifact`/`download-artifact`.** The artifact format doesn't preserve permissions, so anything executable arrives at the consuming job as 644.
- **The script is generated or fetched during the run,** by a `run:` step, `curl`, or an unzip, none of which set the bit for you.
- **Windows line endings.** These usually give `bad interpreter: No such file or directory` rather than permission denied, so this is a weaker candidate, but a `.gitattributes` marking the script `text eol=lf` is worth having anyway.

Adding `chmod +x script.sh` as a workflow step will unblock you today, and it's the right answer for the artifact and generated-file cases, where there's no committed mode to fix. For a script that simply lives in the repo, commit the bit instead: the workaround has to be repeated in every workflow and every clone that runs it.
