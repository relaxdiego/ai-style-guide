Git never recorded the executable bit on that script, so the runner checks it out mode `644`.

Locally the file has `+x` because your filesystem set it when you created it, but git stores mode as either `100644` or `100755` and it defaults to `100644` unless the bit was set *before* `git add`, or you told git afterward. Check with `git ls-files -s path/to/script.sh` — if it starts with `100644`, that's your bug.

Fixes, in order of preference:

| Fix | Command | Notes |
|---|---|---|
| Record the bit in git | `git update-index --chmod=+x path/to/script.sh` then commit | Works regardless of local filesystem or `core.fileMode` |
| Don't rely on the bit | `bash path/to/script.sh` in the workflow | Fine for `run:` steps; won't work for `#!`-dispatched entrypoints or `uses:` actions |
| Chmod in CI | `chmod +x path/to/script.sh` step before use | Papers over it; every consumer of the repo hits the same problem |

Two things that mask this: `core.fileMode=false` (set automatically on Windows and on some mounted filesystems) makes git ignore mode changes entirely, so a plain `chmod +x` locally produces no diff; and a `git diff` after chmod on a normal Linux checkout *does* show `old mode 100644 / new mode 100755`, which is the confirmation you want before committing.
