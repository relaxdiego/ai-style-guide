Git stored the file as mode `100644`, so the CI checkout has no execute bit. Your local copy works because the file kept `+x` from when you created it; that bit was never committed.

Check and fix:

```bash
git ls-files -s ci/build.sh        # 100644 = broken, 100755 = fine
git update-index --chmod=+x ci/build.sh
git commit -m "Make ci/build.sh executable"
```

`chmod +x` alone also works if `core.fileMode` is true, but `git update-index --chmod` sets the index mode regardless.

Common causes of the bit getting dropped:

| Cause | Signal |
|---|---|
| `core.fileMode=false` in your config | `git config core.fileMode` returns `false`; Git ignores local mode changes entirely |
| Repo on Windows, WSL/`ntfs` mount, or a shared drive | Filesystem does not carry the bit; Git defaults `fileMode` to false |
| File created by an editor or generator, never `chmod`ed | Local file is `644` too; `ls -l` shows no `x` |
| Script pulled from a zip/tarball artifact | Extraction dropped modes |

If you would rather not depend on file modes at all, invoke the script through the interpreter in the workflow: `run: bash ci/build.sh`. That is immune to mode loss and to the script missing a shebang, which is the other failure that shows up as `permission denied`-adjacent errors (`exec format error` if the shebang is absent or has CRLF line endings). Check for CRLF too, since `\r` on the shebang line produces `bad interpreter: /bin/bash^M`: `file ci/build.sh` or `sed -n '1p' ci/build.sh | cat -A`.
