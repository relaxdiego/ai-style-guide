Git didn't record the executable bit. Locally the file is `0755` because your shell created it that way; in git's index it's mode `100644`, so the runner checks out a non-executable file and `./script.sh` fails.

Check and fix:

```bash
git ls-files -s path/to/script.sh   # 100644 = the bug, 100755 = fine
git update-index --chmod=+x path/to/script.sh
git commit -m "Mark script.sh executable"
```

Other causes, in the order I'd check them:

| Symptom | Cause | Fix |
|---|---|---|
| `git ls-files -s` shows `100755` already | `core.fileMode=false` locally masked it, or checkout stripped it | Same `--chmod=+x`; verify on the runner with `ls -l` |
| Script came from a zip, artifact, or `actions/download-artifact` | Zip archives don't preserve the bit | `chmod +x` in the workflow step after download |
| Fails only on the first line | Shebang missing or has CRLF | `file script.sh`; add `#!/usr/bin/env bash`, force LF via `.gitattributes` |
| Repo checked out on a case-insensitive or noexec mount | Rare on hosted runners, common on self-hosted | Invoke as `bash script.sh` |

Invoking `bash path/to/script.sh` instead of `./path/to/script.sh` sidesteps the permission bit entirely and is the more robust call in CI, but fix the committed mode anyway so the script works when someone runs it by hand.
