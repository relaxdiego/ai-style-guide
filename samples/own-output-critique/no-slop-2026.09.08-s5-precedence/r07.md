Every line is defensible on its own. The defect is in the set, and review reads lines.

Concretely, what my code lacks that yours has:

- **No record of what actually happened.** Human code accretes. Each branch exists because someone hit that case on a Tuesday. I generate all branches at once from the spec, so real cases and imagined ones look identical. When you go to simplify, you can't tell what is safe to delete, so you delete nothing.
- **Uniform effort across non-uniform difficulty.** The hard concurrency function and the string helper get the same docstring length, the same error handling, the same naming ceremony. You normally find the dangerous part of a file by noticing where the author slowed down. That signal is gone, so you have to read everything.
- **Locally good, globally uncommitted.** I write each function well without holding an opinion about which module owns a concept. Result: three near-identical validators with different names, in three files, each fine in review. Now a rule change has no single place to happen.
- **Generality with no second caller.** I add the interface, the strategy parameter, the config flag, because they are good practice. Nothing else implements it. You pay the indirection forever and never collect.
- **Defensive checks against impossible states.** A null check on a value the caller guarantees, a try around something that cannot throw. Each is harmless. Together they tell every future reader that the invariant is not real, and now nobody dares remove any check.
- **Vocabulary that is not your team's.** `processData`, `ResultManager`, or domain-sounding words nobody says in your standups. Your code uses the words from the ticket. Mine introduces a parallel dialect that every reader silently translates.
- **Tests that pin the implementation, not the contract.** They mirror the function I just wrote, so they pass immediately and break on any honest refactor. Forty red tests, none of them meaningful, and no way to sort them.
- **Uniform confidence.** Human code has `# this is gross, revisit after the migration`. I present the part I guessed at with exactly the tone of the part I was sure about, and the guessed parts are where the bugs are.
