Nothing is wrong with any line. What's missing is the record of the decisions behind the code, and any commitment you can lean on when you change it. Review reads a diff top to bottom and asks "is this correct?" Maintenance asks "what can I delete, and what will break?" I write for the first question.

Concrete mechanisms:

- **No invariant has a home.** I re-validate and re-normalize defensively at every layer because each check is individually harmless. Later you cannot delete any of them, because none is marked as the real one. Human code says "IDs are normalized at the HTTP boundary" once and trusts it after.
- **Uniform error handling instead of considered error handling.** Every call gets wrapped. Nothing distinguishes "impossible, crash" from "expected, retry" from "user's fault." The maintainer inherits a codebase where all failures look equally likely, so none can be simplified away.
- **Abstractions sized for the current diff.** I extract a helper at two call sites because it reads well, without any theory of what will vary. The third case does not fit, and adding a flag is cheaper than reworking it, so it gets a flag.
- **Constants that are plausible rather than derived.** Timeout of 30s, page size of 100, 3 retries. Nobody can tune them because nobody knows whether they were measured or guessed. They were guessed.
- **Comments restate the code.** The reviewer already knew why from the PR, so a missing "why" costs nothing at review time. Two years on, the only thing that explains the retry count is a Slack thread.
- **Vocabulary drift.** `user`, `account`, `principal`, `subject` for one concept, each locally correct because each function was written on its own. Grep stops working.
- **Symmetry imposed on asymmetric problems.** Three handlers get identical structure when one has a genuinely different lifecycle. It reads clean and it hides the one that is different.
- **Tests pinned to the implementation.** I wrote the code, so I test what it does rather than what it promises. Coverage is high, refactors break the suite, real regressions slip through.
- **No failed attempts recorded.** Code written by a person carries scars: the batch endpoint that rate limits, the library version that deadlocks. Mine looks like it worked on the first try, so you will retry the things I already found do not work.

What helps in practice: tell me where the invariants live and make me enforce them in exactly one place; ask me to state which errors are expected and let the rest crash; refuse the second-call-site extraction and wait for the third; and make me write down where each constant came from, including "guessed, unmeasured."
