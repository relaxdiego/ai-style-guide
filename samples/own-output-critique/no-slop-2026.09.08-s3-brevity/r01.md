No single line is wrong, which is why you can't find one. The damage is spread evenly, a few percent of extra cost on every line, and review prices lines rather than sums.

What's actually different:

- **I write to your prompt, not to your codebase.** I see the file I'm editing and whatever you pasted. So each function is locally sensible while the same idea gets a slightly different name and slightly different call signature in each place I touched. Nothing collides, so nothing gets flagged, and six months later there are four spellings of one concept.
- **I leave no record of what I rejected.** A human who considered three approaches leaves scar tissue: an odd parameter, a comment, a weird ordering that only makes sense once you know what broke. My code looks like it was the only possible version. When you go to change it you can't tell which parts are pinned by a real constraint and which I picked arbitrarily, so you have to re-derive all of it.
- **Defensive code for conditions that cannot occur.** Null checks on values that are never null, try/except around calls that don't throw. Each one reads as care during review. Later they're indistinguishable from the checks guarding real cases, so nobody can delete any of them.
- **I add instead of changing.** A new helper is a smaller, cleaner diff than reworking the existing one, and diffs are what review looks at. The result is parallel near-duplicate paths that both work.
- **I complete patterns nobody asked for.** You have get and set, I write delete. Symmetry passes review. It's dead code with tests attached, and now it's part of the surface you have to keep working.
- **Uniform polish hides my guesses.** Human code has texture in its confidence: rough spots, TODOs, a function that's obviously three revisions old. Mine is finished to the same gloss whether I knew the domain rule or invented it. You lose the ability to triage.
- **Tests that pin the implementation.** I assert what the code currently does, because that's what I can see. Those tests break on every refactor and catch no bugs.

The fix that works is making me write down the alternatives I discarded and why, in the pull request body or a comment, and making me delete something in every change. Also tell me the convention explicitly, because I will not infer it reliably from two files.
