The code has no record of what I was uncertain about, and everything is written at the same level of confidence.

Code that a person maintained accretes evidence. The odd null check exists because something came back null at 3am. The weird ordering exists because a previous ordering deadlocked. When you read it later, you can tell the deliberate parts from the incidental ones, so you know what is safe to delete. I emit the odd check and the ordinary one in the same keystroke, with the same tone, and nothing in the file distinguishes "this guards a real failure I know about" from "this seemed prudent." So every line is undeletable. That is the feeling you can't point at: you can't refactor because you can't tell what is holding something up.

The specific habits that produce it:

- **Defensive filler.** Null checks, try/except, fallback values where the invariant already holds. Individually justifiable, so review passes. Collectively they erase the signal that a real guard would have carried.
- **Names for the operation, not the reason.** I write `validateInput` where you would have written `rejectPre2019ImportFormat`. The behavior survives, the reason it exists does not.
- **Uniform error handling.** I wrap everything the same way instead of grading it, so "cannot happen" and "happens weekly" look identical in the source.
- **Local style match, global inconsistency.** I copy the idioms of the file in front of me, then pick a different decomposition than you would have on the next file. Nothing is wrong in any diff. The codebase drifts into three shapes for one idea.
- **Irregularity smoothed away.** Real domains have exceptions. I tend to produce code more regular than the problem, so the first genuinely irregular case has no place to go and gets bolted on badly.
- **Comments that restate the code.** The line that mattered was the one recording what you tried and why it failed, and I did not have that to write down.
- **Abstraction fitted to the stated requirement.** Parameterized along the dimension you named rather than the one that varies later.

What changes it: tell me the history and the constraints, not only the target behavior, and ask me to mark which guards I actually have evidence for. Then delete the rest immediately, while you still know which is which.
