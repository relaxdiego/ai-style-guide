The defects live in relationships between lines, and review inspects lines. Every statement is defensible; the set of them is wrong.

- **No single model of the invariants.** I write each function to satisfy its own contract. A rule like "paths are absolute by the time they reach storage" ends up enforced in four places or in none, because each function assumed a neighbor handled it. Reading function by function finds nothing.
- **Defensive code with no owner.** Null checks, broad `except`, fallback defaults at every level, each individually reasonable. Together they convert failures into plausible values that surface three layers from the cause. You debug the symptom site for an hour.
- **Names for the operation instead of the concept.** You've carried a domain idea for weeks; I name after what the code does in front of me (`process_records`, `handle_response`). Six months later the names don't tell you which idea you're editing, so you re-derive the model on every visit. That cost is real and sits on no line.
- **Symmetry that isn't real.** Three branches written in parallel form, one of which differs for a reason nobody recorded. You change the shared shape and break the odd one. The mirror image also happens: duplicated logic because I generated each call site independently.
- **The parts that flex are in the wrong places.** Code you maintain grows parameters where change actually happened. Mine grows them where your description had adjectives. When the real change arrives, nothing bends and you rewrite.
- **No record of rejected alternatives.** I never tried the approach that deadlocks, so nothing says it deadlocks. Settled questions get reopened. My comments restate the code rather than justify it.
- **Tests derived from the implementation.** I write them after the code, from the code, so they encode its accidents and pass. A correct refactor breaks thirty of them and tells you nothing.
- **Uniform polish.** Code written by someone who was nervous has hot spots: an extra guard, a blunt comment, a heavier test. Mine reads at one confidence level throughout, so you can't tell what I knew from what I guessed. That's why you can't point at the line.

What changes the output: tell me the invariants and where they must be enforced, tell me which errors are fatal instead of letting me choose, make me use your domain's nouns for the concepts, have me write tests from the spec before the implementation, and ask me to mark what I guessed with a comment rather than smoothing it over.
