My code carries no history and no prediction. Every line looks equally deliberate because none of it is, and maintenance is mostly the work of telling deliberate choices from defaults.

Concretely, the things that differ:

- **I factor out what repeats textually, not what changes together.** The helper is real duplication removal and reviews fine. Six months later one caller needs different behavior, and the helper has no natural place to put it, because it was never a concept, only a shared shape.
- **Uniform density of care.** I validate, log, and handle errors at roughly the same intensity everywhere. Human code has peaks where someone got burned. Reading mine tells you nothing about where the risk lives, so you have to re-derive that yourself every time.
- **No record of prior fights.** Your existing code has a weird retry, an odd ordering, a field set twice, all of which are scars. Mine has none, and also no marker saying "this was arbitrary." So you can't tell which of my lines you're allowed to change.
- **Names describe mechanism, not domain.** `processResults`, `handleUpdate`, `Options`. Correct, unobjectionable, and they carry zero information about the invariant you must not break.
- **Speculative generality in the wrong dimension.** I add a config flag or an options bag for the variation I could see from the function body, and hardcode the one your product will actually need to vary.
- **Tests that pin behavior instead of requirements.** They pass now and they break on every legitimate refactor, which teaches you to distrust the suite.
- **Local consistency, global drift.** I match the file in front of me. If I never read the three other places that solve the same problem, I add a fourth idiom that no one will reconcile.

The lever that fixes most of this is information I don't have and rarely ask for: what is likely to change next, what already went wrong here, and which existing file is the pattern to copy. Give me those in one or two sentences with the task, and ask me to flag the choices I made arbitrarily so you know where you're free to edit. That last one costs me a few comments and removes most of the "something is off and I can't point at it" feeling.
