The code has no record of which decisions were forced and which were arbitrary. A person writing it accumulates constraints over hours or weeks, and the result carries evidence of that: a weird branch that exists because of a real bug, a comment clustered exactly where they got confused, a plain loop where they didn't care. I produce all of it in one pass at uniform confidence, so every line looks equally deliberate. When you go to change something, there's nothing telling you which parts are safe to touch.

Concretely, what shows up:

- **Conventions invented per file.** I only see the code you showed me. So error handling here uses a Result type, error handling three modules over raises. Each passes review alone; together there's no rule you can apply without reading everything.
- **Abstractions with one caller.** A parameter, a hook, a base class introduced because that's the shape of a general solution, not because a second call site demanded it. Nothing constrained the design, so when the second use arrives, the abstraction is subtly wrong and you can't tell whether it was meant to cover that case.
- **Defensive code on paths that can't happen.** Null checks and fallbacks for impossible states read as responsible in review. Later nobody can tell if the check is guarding something real, so it survives forever and hides the actual bug when it happens.
- **Tests derived from the implementation.** I write them from the code I just wrote, so they encode its current structure instead of the requirement. Coverage looks good, they break on every honest refactor, and they miss the regressions that matter.
- **Category names.** `handleData`, `processResult`, `normalize`. Fine when the reviewer has the context loaded, empty six months later.
- **Assumptions never written down.** I picked a behavior for the ambiguous case and didn't say so. You inherit the decision without the question that preceded it.

The fix that works: when I hand you something, ask which parts were forced by a constraint and which I chose freely, and make me delete the generality that has one caller. Ask what I assumed about the cases you didn't specify. That reasoning exists while I'm writing and disappears the moment I stop, and it's the thing you're missing later, not a line in the diff.
