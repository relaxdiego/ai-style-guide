No individual line is wrong. What's missing is spread across the file: the record of which decisions were deliberate. When you write code, you spend attention unevenly, and that unevenness is itself information. The tricky branch gets a comment, the boring loop gets none, the validation you argued about gets a name that reflects the argument. A maintainer reads that distribution to figure out what's safe to change. My code has a flat distribution: every function gets the same grade of care, so nothing stands out, and you have to re-derive every decision from scratch.

Concretely, the things that produce that feeling:

- **Defensive checks for impossible states.** A null guard on a value that's constructed three lines up. Each one passes review as harmless. Together they tell you the input is untrusted, so you preserve an invariant that never existed.
- **Both branches instead of a decision.** Where a reason existed to pick one behavior, I handle two. Now the codebase has two behaviors to keep alive and no note saying which one matters.
- **Abstraction at the first caller.** Parameters for variation I imagined rather than variation you had. The extension point is in the wrong place, and moving it means unwinding the indirection.
- **Names for shape, not domain.** `process_data`, `handle_response`, `result`. Correct, reviewable, and ungreppable when you're hunting for where a concept lives.
- **Style matched, rules not.** I copy your formatting and import order reliably. The unwritten conventions (this layer never touches the DB, errors bubble to one place) I only follow where an example was in front of me.
- **Tests that encode the implementation.** They pass now and they'll pass after someone breaks the requirement, because they assert what the code does rather than what it owes the caller.

The fix on your side is to ask for the reasons, not more code: make me state what I assumed, which cases I deliberately excluded, and where I guessed. Delete the guards I can't justify and the parameters with one caller. If I can't say why a line is there, that's the line.
