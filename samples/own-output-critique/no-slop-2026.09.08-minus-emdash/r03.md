Nothing is wrong at any line, and review looks at lines. The code I write is locally defensible everywhere and has no consistent policy anywhere, so the cost only shows up when you try to change it.

The specific mechanisms:

- **Uniform defensiveness.** I put the same null check, try/except, and fallback default around code that can fail and code that cannot. Hand-written code varies its check density, and that variation tells you where the author had been burned. Mine tells you nothing, so you can't distinguish a guard that's holding something up from decoration.
- **No record of why.** I write code from the spec as it stands, so there's no trace of the bug that made a branch necessary. Comments I add restate what the line does. Six months later you can't delete anything, because nothing in the file says whether a case is real or imagined.
- **Abstraction from surface similarity.** I extract a helper when two call sites look alike today, not when they've actually changed together. When they diverge you get a boolean parameter threaded through the shared function, and then a second one.
- **I match your style without adopting your invariants.** I'll copy naming and formatting and error-wrapping from the surrounding file, then re-validate an ID that the boundary already validated, or raise from a module that has never raised. It reads native and violates a rule the module was relying on.
- **Per-function decisions instead of one policy.** Error handling, config access, and clock reads get settled independently in each function I touch. Each diff is small enough to pass. The file ends up with three ways to do the same thing and no way to tell which is current.
- **Generality that looks free.** An optional parameter, a hook, an interface with one implementation. Zero cost at review, and it pins the design when you need to change it.

What helps, concretely: tell me the invariants the module maintains rather than only the behavior you want, ask me to write down the reason for a guard or drop the guard, tell me not to extract a helper until the second caller actually diverges, and have me write tests against the public interface before the implementation exists, so they don't mirror the code I just wrote.
