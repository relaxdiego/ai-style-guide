The defect is in the relationships between parts, not in any part, which is exactly why no line looks wrong. Review checks each function against its own contract; maintenance requires a single idea of how the system works, and I don't have one to transmit. I produce code that is locally defensible everywhere and globally uncommitted.

Concretely, here's what shows up in my output:

- **Defensive checks I can't justify.** I don't know which invariants hold upstream, so I null-check, try/except, and default-fallback at every level. You can't delete any of them later because you can't tell which ones are real. Dead error paths that are untestable and unremovable.
- **No record of rejected alternatives.** A human writes `# retry: this API returns 200 with an empty body`. I write the retry. Six months on you can't tell whether the retry is essential or superstition, so you keep it.
- **Names that describe mechanics instead of domain roles.** `process_data`, `handle_response`, `_normalize_input`. These tell you what the code does, never what it's allowed to become. You lose the ability to reason about which changes are safe.
- **Abstractions sized to the current diff.** One helper with one caller, or three near-copies where a human would have picked. Either is fine in isolation; both are wrong as a set.
- **Tests that mirror the implementation.** They pass, they break on any refactor, and they catch nothing. They constrain the shape of the code rather than its behavior.
- **No memory across sessions.** Feature three doesn't extend the abstraction from feature one, it grows a parallel one. Each is reviewable. The union is a mess.
- **Style-matching that hides all of the above.** I copy your formatting and idiom, so the code reads as yours in review, while the design decisions inside it are mine and unstated.

What actually helps: tell me the invariants and I'll delete the defensive noise instead of guessing; make me state the design in prose before writing (if I can't, the code will be incoherent); ask for the alternatives I rejected and why, in comments, at the point of decision; and hand me the existing abstraction to extend by name rather than letting me discover a new one.
