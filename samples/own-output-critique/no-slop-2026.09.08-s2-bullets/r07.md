Every line comes out with the same confidence, whether it was a requirement you gave me or a guess I made. Review checks whether each line is defensible in isolation, and my guesses are individually defensible. Maintenance needs the opposite information: which lines you're allowed to delete. That signal is missing, so the file resists change everywhere at once and you can't point at where.

The specific mechanisms:

- **Guards against states that can't occur.** A null check on a value whose only caller constructs it, a `try/except` around code that doesn't throw. Each one reads as prudence. Six months later you can't tell "this can be null" from "I was hedging," so you leave all of them, and the real precondition is now invisible among the fake ones.
- **Constants with no recorded reason.** `timeout=30`, `max_retries=3`, batch size 100. I picked those. They look like they came from measurement, so nobody touches them, and nobody knows what breaks if they change.
- **Uniform polish.** I factor the throwaway CLI parser as carefully as the core loop. Human codebases are uneven, and the unevenness tells you where the thinking went. Mine is flat, so nothing marks the parts that matter.
- **Names that describe the code, not your domain.** `process_data`, `handle_response`, `validate_input`. They match their bodies, so review passes. They can't drift from the domain because they never touched it, which means you never get the useful failure where a name stops matching what the thing does.
- **Parameters with one caller.** A flag, an optional argument, a strategy hook, all with exactly one value in the whole tree. Cheap to add during review. Every later reader has to check all call sites to learn the flag is always `True`.
- **Comments that restate the line above.** The reason a thing exists goes unwritten, including the alternatives I rejected while writing it.
- **Tests written against my implementation.** They pass on commit and pin incidental behavior. Change something on purpose and a dozen assertions fail for reasons unrelated to your change.

What fixes it is telling me the preconditions the callers actually guarantee, so I have no excuse to hedge, and then asking me to list every choice I made that you didn't specify: each guard, each constant, each parameter. Delete the ones that were mine. The code that survives is the code you can reason about later.
