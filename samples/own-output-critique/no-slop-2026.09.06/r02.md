The code is locally correct everywhere and committed to nothing. A person writing the same feature accumulates decisions across files: this module owns validation, dates get parsed exactly here, failures in this layer raise and never return None. I re-derive that choice per function, fresh, from whatever was in front of me. Nothing contradicts anything, so review passes, and there is no rule you can lean on later either. Every change means re-reading the whole path because no invariant is guaranteed anywhere.

Concretely, the things you can't point at:

- **Uniform caution.** I null-check arguments the caller already validated, because I can't see the caller's guarantees. Now every check looks the same and none carries information. You can't delete one without proving it, and you can't tell which ones are real.
- **Flat density.** The error branch gets the same care as the hot path; a three-line helper gets the same ceremony as the core algorithm. Human code varies, and the variance tells you where the risk was. Mine forces equal attention on all of it.
- **Silent decisions.** Where the spec was ambiguous I picked something reasonable and left no trace. The result reads as settled rather than as a coin flip, so nobody revisits it when the assumption breaks.
- **Vocabulary drift.** `fetchUser`, `getUserRecord`, `loadUserData` in three files for one concept. Each diff is fine alone; the collision only exists in aggregate, which is not what review looks at. Later, grep misses things.
- **Speculative parameters.** Options and flags for cases that don't exist yet. Harmless per line, permanent as API surface, because nobody can prove they're unused.
- **Boundaries at conversation joints.** Modules split where our turns split, not where the domain splits.

Every item there is a property of the whole or of something absent, and a diff shows neither. What helps: tell me the invariants and the existing names before I write, and ask me afterward what I decided without being told, then have me write those down as assertions or comments so the next reader sees the coin flip instead of the confident line.
