Every defect is an absence, and review only inspects what's present. Nothing on the screen is wrong, so there's no line to point at.

What's missing, concretely:

- **No history of compression.** Your code has an abstraction because something needed it twice. Mine has one because it looked like the right size. You can't tell which parts are load-bearing structure and which are decoration, so every change feels like it might be the one that matters.
- **Uniform defensiveness.** I null-check at every level instead of establishing one validation boundary and trusting everything inside it. The result: you can never infer from the code where bad data actually enters. Every function looks equally exposed.
- **Names accurate to the local role, empty about the domain.** `handleResponse`, `processItem`, `opts`. Correct enough to pass review, carrying zero information about which invariant the thing protects.
- **Comments that restate rather than record.** The rejected alternative is gone. Six months later you can't tell whether the strange branch is a deliberate workaround for a broken upstream API or an artifact.
- **Flat importance topology.** No hot path, no core-versus-edge distinction, no signal about what's incidental. Human code has a center of gravity; mine has uniform density.
- **Error handling that's syntactically complete and semantically empty.** Catch, log, return a default — and the default silently becomes valid input to the next function.
- **Local consistency, global divergence.** I solve a problem the codebase already solved, in a slightly different way, in a new file. Each file reviews clean.

The fix is in what you ask for, not in reviewing harder: tell me the invariants you want enforced and where the trust boundary sits, name the existing module I should be consistent with, and require that anything non-obvious carries the alternative it beat. If you want the leverage in one place, make me write the tests that encode intent before the implementation — those are the guardrails that turn a later refactor from archaeology into a mechanical change.
