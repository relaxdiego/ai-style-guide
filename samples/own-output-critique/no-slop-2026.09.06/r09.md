Every line is defensible; the set of lines carries less information per line than code a person wrote, and nothing tells you which lines you're allowed to delete. Maintenance is mostly deletion and change, and both need to know which constraints are real. Human code is a record of decisions — each odd branch traces to a bug, a deadline, or an incident. What I produce is a plausible sample from the average of a lot of code, which means it looks like a record of decisions without being one.

The specific ways that shows up:

- **Uniform confidence.** No TODO, no hedge, no visibly ugly part. A person's code signals where they were unsure, and that gradient is what you use to triage when it breaks at 3am. Mine reads equally sure everywhere.
- **Defensive code with no incident behind it.** A null check, a broad `except`, a retry. You can't delete it because you can't prove it's dead, and you can't trust it because it may be swallowing the real failure. Every one of these is a permanent small tax.
- **Abstractions written before the third call site existed.** A parameter every caller passes the same value for, a flag never set false, an interface with one implementation. Extracted abstractions fit the real uses; invented ones fit an imagined set.
- **False parallelism.** Three branches formatted identically when the third case doesn't share the structure. It reads as a pattern, so you extend it as a pattern, and the bug lands in the third branch.
- **Names describing mechanism, not domain.** `process_data`, `handle_item`, `validate_input`. Nothing compresses, so you re-read the body every time instead of trusting the name.
- **Consistency inside the diff instead of with the repo.** I match my own file, not your existing way of doing the same thing. Each instance is fine; the sixth parallel convention is what costs you.
- **No cost model.** I don't know what's hot, what runs once at boot, or what your on-call actually pages on, so care gets spread evenly rather than concentrated.

Things you can demand that fix most of it: make me mark which lines are guesses versus which I can justify; make me name the existing file in your repo I matched, so the convention question gets answered explicitly; refuse any parameter without two real callers; require every defensive check to state the invariant it protects in a comment, and delete the ones where I can't; ask for the smallest diff that passes the test and make me argue for anything beyond it.
