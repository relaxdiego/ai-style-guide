The defects are statistical properties of the whole file, not facts about any line. Review reads diffs line by line, and every line is defensible, so nothing gets caught. Here is what is actually different:

- **No invariants are asserted, so none can be inferred.** I add a null check or a `try/except` because that is the shape of careful code, not because I decided the value can be null. Every future change has to re-derive the contract from scratch.
- **Uniform finish.** Human code has hot spots. The gnarly concurrency function gets four comments and careful naming; the config loader below it is three terse lines. That gradient tells the next reader where the danger is. Mine is evenly polished across the file, so it carries no map.
