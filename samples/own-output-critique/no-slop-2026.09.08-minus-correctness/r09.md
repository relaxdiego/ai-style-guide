Concretely, the things that bite you later:

- **Guards at uniform weight.** A null check for an input that cannot be null sits next to one catching a real bug, written identically. You can't tell which one you're allowed to delete.
- **Decomposition follows your prompt, not your roadmap.** I split functions along the nouns in your request. The next feature cuts across all of them, so a one-concept change touches five files.
- **Names describe the code's own structure.** `processResult`, `handleItem`, `validateInput`. Reading them teaches you nothing about your domain, so the file can't onboard anyone.
- **Near-duplicate blocks differing in one detail,** with nothing indicating whether the difference is deliberate or drift.
- **Abstractions with one caller,** built because the pattern looked right rather than because a second case forced it.
