Reviewers check whether each line is correct. Maintainers need to know why each line exists, and that information is exactly what I don't have and don't mark as missing.

Concretely, what shows up in my code:

- **Defensive branches for failures that can't occur.** Null checks on values the only caller can't produce, try/except around calls that don't raise. Each one reads as robustness in review. Each one tells a future maintainer "someone saw this fail," so they spend an hour looking for the caller that passes null. It doesn't exist.
- **Abstractions with one caller.** A helper, an interface, a config parameter added for a second use case that never arrives. It looks like design. It costs indirection forever and pays nothing.
- **Locally consistent, globally incoherent.** I match the file in front of me. Across ten files I'll solve the same problem three ways, all reasonable in isolation. No diff is wrong; the codebase has no single way to do anything.
- **Comments that restate the code and never record a decision.** Why 30 seconds, why retry only on 503, why this order: I usually guessed, and a guess is written in the same confident tone as a requirement. Nothing distinguishes the number that matters from the number I made up.
- **Tests derived from the implementation.** Written after the code by reading the code, so they assert what it does rather than what it should do. They pass, they cover the lines, they pin the bugs in place, and they break during honest refactors. You learn to ignore them.
- **Completeness beyond the problem.** All the flags, all the config fields, all the error cases enumerated. More surface than you asked for, and you own every bit of it.

The fix is mostly instructions to me: say "no defensive code for conditions that can't happen here," "no abstraction until there's a second caller," "mark every value you guessed with a TODO naming what you'd need to know," and hand me the existing pattern to copy rather than letting me invent a fourth one. For tests, give me the cases or the spec before I write the implementation, otherwise they're just a mirror.
