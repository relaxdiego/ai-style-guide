The lines are fine individually. What's missing is any way for a later reader to tell which decisions were forced and which were arbitrary, so every line has to be treated as if something depends on it.

Concretely, the recurring mechanisms:

- **No history.** Code that grew over time has branches that correspond to bugs someone actually hit. Mine arrives whole and uniform, so you can't tell the check that prevents a production incident from the check I added because it looked tidy. You end up unable to delete anything.
- **Error handling at the wrong level.** I put `try`/`except`, null checks, and default fallbacks in the function I'm currently writing rather than at the boundary where the invariant should be established. Reviewers see "handles failure" and approve. Later, a bad value travels three layers before surfacing, and the stack trace points at the wrong place.
- **Flexibility in the dimension that doesn't vary.** I pick abstractions by what shape is common (config dict, dispatch table, injected callback), not by what this system is likely to change. So the parameter you need to change is hardcoded and the one nobody touches is configurable.
- **A second vocabulary for an existing concept.** Asked for a feature, I write it to satisfy the request rather than to fit what's already there, and produce `fetch_user_record` next to your existing `load_account`. Each passes review. Now grep doesn't find the concept.
- **Comments that restate the code.** `# increment the counter`. The reason the counter exists is gone permanently, and that reason was the only thing worth writing down.
- **Uniform thoroughness.** Every function gets the same docstring, the same validation, the same care. Human code varies, and that variance is a signal about where the subtle parts are. Mine flattens it, so nothing warns you before you break something.
- **Tests derived from the implementation.** I write them by reading the code I just produced, so they lock in current behavior including its bugs, and they fail on refactor instead of on regression.

The fix on your side is cheap: tell me the invariant and where it's enforced before I write, and after I write ask "which of these lines can I delete and what breaks." Also make me justify every abstraction by naming the change it's meant to absorb; if I can't name one, it comes out.
