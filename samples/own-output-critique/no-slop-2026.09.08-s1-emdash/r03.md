The defect is distributed, which is why there's no line to point at. Every individual line is defensible; the cost lands in how many decisions you have to hold in your head to change anything.

What's actually different:

- **Rules get re-derived at each call site instead of stored in one place.** I satisfy the spec everywhere it applies rather than picking the one function that owns the invariant. Nothing is wrong, and there's no place to go when the rule changes.
- **Branches you can't delete.** Null checks, fallbacks, and `else` clauses for inputs that cannot occur. You can't tell which cases are real, so you preserve all of them forever.
- **Helpers with one caller.** I extract three repeated lines into a named function, which buries the actual structure of the problem behind a layer that exists only because I wanted to avoid repetition.
- **Uniform difficulty.** Code you write has three hard lines and forty boring ones. Mine elaborates everything at the same level, so you can't skim, and the part that deserves attention isn't marked as deserving it.
- **No reason attached to anything.** A retry loop I added on general principle and a retry loop that exists because of a specific outage look identical. Nothing can be safely removed, so the file only grows.
- **Fresh vocabulary.** I name a concept at the moment of writing instead of reusing the word already in your codebase for it. Now there are two names for one thing and no search finds both.
- **Style matched to the file, not the codebase.** I read what I'm editing, not the three files that establish the convention. Each edit is plausible alone; the set pulls apart.
- **Tests that encode the implementation.** They assert what the code does, so they pass when the code is wrong and fail when you refactor correctly.

The fix is in what you demand before I write. Ask me which single function owns the invariant and make me put it there. Ask me to justify each branch by naming an input that reaches it, and delete the ones I can't defend. Refuse helpers with one caller. Ask what I deleted, not just what I added. Give me the five domain words your codebase uses and require me to use exactly those.
