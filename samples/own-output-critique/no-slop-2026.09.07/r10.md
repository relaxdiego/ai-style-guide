The specific mechanisms:

- **No room for the next case.** You describe three cases, I write three cases. A person who has worked on the thing writes the same three but arranges them so the fourth costs one branch. Mine is correct and the fourth case costs a rewrite of the dispatch.
- **Uniform care.** I put the same density of validation, logging and error handling on the trivial path as on the one that can corrupt data. Human code is cheap in cheap places, and that unevenness is how a maintainer finds the dangerous part in thirty seconds. Flattening it deletes the signal without deleting any information.
- **Names drawn from your sentence, not your codebase.** You say "process the user data" and I write `processUserData`, in a repo that has called that record a `Subscriber` for two years. Each name is fine. The set doesn't compose, and six months later there are two vocabularies for one thing.
- **Abstraction placed by resemblance instead of by what changes together.** Two functions that look alike get factored into one. They looked alike by accident, they change for different reasons, and the next feature has to tear the helper apart before it can start.
- **Silent resolution of holes in the spec.** Where your description was ambiguous, a person leaves a TODO or asks. I pick the plausible reading and render it in code that looks decided. Nothing marks the spot, so the assumption gets built on.
- **Locally chosen defaults.** A 30 second timeout here, 5 retries there, a page size of 100. Every value is sane in isolation and none of them came from your config or matches the numbers next door.
- **No record of what was rejected.** Real code carries "don't use the batch endpoint here, it reorders under concurrency." I emit the surviving answer only, so the next person walks into the same wall and pays the same cost to learn.
- **Tests that mirror the implementation.** I test the code I just wrote rather than the contract you wanted, so the suite is green and would stay green if the behavior were wrong in the way you actually care about.

Review catches bad lines. Every item above is a property of the whole set of choices, so there is no line to flag, and the cost only shows up at the second change.
