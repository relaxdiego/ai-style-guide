In code you wrote yourself, the irregular parts mark where reality pushed back: the odd retry count, the check that looks paranoid, the function that resisted being split. Mine has one register throughout, so the information about what is safe to change was never written down. No single line is defective, which is why you can't find one.

The specific mechanisms:

- **Defensive code with no incident behind it.** A null check on a value that cannot be null, a try/except around a call that does not raise. Review passes because it is harmless. Two years later you cannot delete it, because you cannot prove the case never occurs, so it stays forever and every reader spends attention on it.
- **Abstraction at two callers.** You would write the second copy and wait. I write the parameterized helper immediately. It is correct and buys nothing, and when the third caller arrives it does not fit, so someone adds a boolean argument.
- **Parallel structure over a domain that is not parallel.** Three handlers written to look alike when only two really are. The odd one then grows a special case inside a structure built to deny it has one.
- **Comments that restate the code.** `// retry 3 times` instead of `// API 500s on cold start, 3 covers it`. The reasons were never in my context, so they are not in the file, and the next person re-argues a decision that was already settled.
- **Tests that mirror the implementation.** They assert the function does what the function does, with mocks arranged to match the call order I happened to write. They pass, they cover the lines, they pin nothing you care about. Refactoring breaks them without finding a bug.
- **General programming vocabulary instead of your domain's.** Manager, handler, process, data, result. Names are consistent, so review passes. The code stops teaching the domain, and the next maintainer goes back to the ticket to find out what it does.
- **Errors converted into plausible values.** Empty list on failure, default on missing config. It looks like error handling. It produces a bug report six weeks later that says "the report was blank" with nothing in the logs.
