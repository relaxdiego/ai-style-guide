TCP congestion control is a feedback loop that guesses the network's available capacity, because no one tells the sender what it is. The sender maintains a congestion window (`cwnd`), sends at most `min(cwnd, rwnd)` bytes unacknowledged, and adjusts `cwnd` based on whether packets arrive. Flow control (`rwnd`, advertised by the receiver) protects the receiver's buffer; congestion control protects the network in between. They are separate mechanisms that happen to clamp the same send rate.

## The signals

A sender has only indirect evidence about the path:

- **Duplicate ACKs** — three dup ACKs mean a packet was lost but later packets got through, so the path still works. Mild signal.
- **Retransmission timeout (RTO)** — no ACK at all within the timeout. Severe signal; the sender assumes the path collapsed.
- **RTT increase** — queues are filling. Delay-based algorithms (Vegas, BBR) act on this before loss happens.
- **ECN marks** — a router sets a bit instead of dropping. Explicit congestion notification without loss, if both endpoints and the path support it.

## The classic state machine (Reno/NewReno)

| Phase | Trigger to enter | `cwnd` behaviour | Exit |
|---|---|---|---|
| Slow start | Connection open, or after RTO | +1 MSS per ACK, i.e. doubles per RTT | `cwnd ≥ ssthresh`, or loss |
| Congestion avoidance | `cwnd` crosses `ssthresh` | +1 MSS per RTT (additive increase) | Loss |
| Fast retransmit / fast recovery | 3 duplicate ACKs | `ssthresh = cwnd/2`, `cwnd = ssthresh` (multiplicative decrease), retransmit immediately | ACK for new data |
| RTO | Timer expires | `ssthresh = cwnd/2`, `cwnd = 1 MSS`, back to slow start | `cwnd ≥ ssthresh` |

"Slow start" is a bad name: it is the fastest phase, exponential growth. It is slow only relative to the pre-1988 behaviour of blasting a full window immediately, which is what caused the congestion collapses Van Jacobson was fixing.

The additive-increase/multiplicative-decrease (AIMD) pattern is not arbitrary. Chiu and Jain showed that among linear control rules, AIMD is the one that converges to a fair, efficient allocation when multiple flows share a bottleneck: increasing by a constant and decreasing by a proportion pushes competing flows toward equal shares regardless of where they start. Additive-increase/additive-decrease does not converge, and multiplicative-increase oscillates.

## Where the classic algorithm breaks

Reno's per-RTT additive increase is too slow for modern links. To sustain 10 Gbps at 100 ms RTT with 1500-byte packets, you need a window near 83,000 packets, and recovering that after one loss takes hours of pure AIMD. Two families of fixes dominate:

- **CUBIC** (Linux default since 2.6.19) replaces linear growth with a cubic function of time since the last loss. It probes aggressively far from the previous loss point, flattens near it, then accelerates again if no loss appears. Growth is independent of RTT, so short-RTT flows do not starve long-RTT ones as badly as under Reno.
- **BBR** (Google, 2016) ignores loss as a congestion signal. It estimates bottleneck bandwidth and minimum RTT separately, then paces at `BtlBw` with an inflight cap around the bandwidth-delay product. It periodically probes up 25% to find more bandwidth and down to re-measure the true minimum RTT.

## Bufferbloat, which is the reason BBR exists

Loss-based control fills every buffer on the path before it backs off, because loss is the only signal it reads. An oversized router buffer therefore adds seconds of queuing latency while throughput looks fine, and interactive traffic sharing that queue becomes unusable. Two responses: active queue management at the router (CoDel, FQ-CoDel, fq_pie) drops or marks early based on sojourn time rather than buffer occupancy, and delay-based senders like BBR stop pushing once RTT rises. ECN plus AQM is the cleanest combination, since it signals congestion without losing data at all, but deployment has been slow because middleboxes historically mangled the bits.

## Practical handles on Linux

```
sysctl net.ipv4.tcp_congestion_control      # current default
sysctl net.ipv4.tcp_available_congestion_control
ss -ti                                       # per-socket cwnd, ssthresh, rtt, retrans
```

Per-socket override is `setsockopt(fd, IPPROTO_TCP, TCP_CONGESTION, "bbr", 3)`. If you switch to BBR, enable `fq` or `fq_codel` as the qdisc; BBR depends on pacing, and while it has internal pacing now, the qdisc does it more accurately.
